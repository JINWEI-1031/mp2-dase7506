## 设计 (Design)

**假设（可证伪）**
把「答案形态」（方案 14 的 `shape`）与「算式重执行」（方案 15 的 `NGSC`）作为**新的基础打分器**
加入方案 11 的 OOF stacking 框架，可在**不牺牲 `k≥2`** 的前提下同时提升 validation `test_like`
与真实 test，超过 `87.32 / 83.30`。

**方法（输入 → 特征 → 打分 → 选择）**
1. 每题 4 个候选各抽 **6 族置换不变特征**：
   `TEXT(31)`（文本/自洽统计）、`GROUP(9)`（组内长度秩/众数/量级秩）、`VOTE(8)`（答案共识）、
   `EMBED(1024, 题内去均值)`，**新增** `SHAPE(7)`（是否整数/分数/负数、`log|答案|`、
   `|答案|/max(题干数字)`、答案在自身文本中的密度、等于题干数字的个数）、
   **新增** `NGSC(9)`（答案是否在题干数字的 `+−×÷` 深度≤2 闭包内、最短深度、闭包规模；
   候选文本里 `LHS = RHS` 片段能否被**符号化重执行**、末式右端是否等于最终答案）。
   候选下标 0..3 从不进入特征。
2. **6 个基础打分器**（全部只在 train 的**类 test 结构子集** `1≤k≤3 且解析值种类≥2`（2114/4755）上、按 `1/k` 加权训练）：
   | 名称 | 特征块 | 打分器 | 损失 |
   |---|---|---|---|
   | `text` | text+group | 逐候选 LR | 二分类 |
   | `embed` | embed | 逐候选 LR | 二分类 |
   | `pair` | text+group+embed | 线性 | Bradley-Terry 成对 |
   | `pairab` | embed | 线性 | Bradley-Terry 成对 |
   | **`shape`** | **embed+shape** | 逐候选 LR | 二分类 |
   | **`ngsc`** | **ngsc** | 逐候选 LR | 二分类 |
3. **K=10 折 OOF**：每折用其余 9 折训练全部基础模型、对留出折打分，拼成元特征矩阵。
4. **元特征**（27 维，只用 15 维）：各基础分数的**组内 z**、组内平均秩、是否组内第一、`n_bases_top1`，
   加 8 维组内一致性统计（投票占比/是否众数/是否并列/票差/是否孤例/解析失败/众数占比/解析值种类数）。
5. **元学习器：Bradley-Terry 成对损失**（方案 11 证明增益来自**成对损失**而非"学习"本身）；每题 `argmax`。

- **关键设计选择（均由数据决定，见证据）**
  1. **`shape` 必须与嵌入绑定**：把 `shape` 接到 `text+group` 上（第一版设计）反而掉分
     （6 基 86.48 → 85.92）；接到 **embed** 上（复现方案 14 的 `emb+shape` 最优视图）才从 86.48 升到 **87.89**。
  2. **`NGSC` 必须独立成路**（不与 `text+group` 绑定），否则被文本族吸收。
  3. **`vote` / `voteaware` 两路去掉**：方案 11 已测其边际为 0；方案 14 复现"投票特征会把 k=1 打到 36.84"。
     去掉后 k=1 从 68.42 升到 **69.30**，而 `k≥2` 不变。
  4. **两段式选型（预注册）**：候选基座集合先按 **train-only 元 CV** 排序取 0.2 点并列带，
     再在 validation 上打破并列（协议明确把 validation 用于选型）；**test 从未参与任何拟合/调参/选择**。
- **被否决的替代方案**：逐候选元损失（−3.66，方案 11 结论在本方案复现：point 84.51 vs pair 88.17）；
  `shape` 接文本族（−1.97）；8 路基座字面融合（`literal_8` 87.61，k2 掉到 92.86）；`NGSC` 接文本族（+0.00）。

**预期（事前可证伪）**：`shape` 与 `NGSC` 应各自带来正增益；若被强基线吸收，则增益为 0 甚至为负。

### G. OOF vs in-fold：泄漏量化（部署配置，元损失 = pair，C=0.3）

| 元分数来源 | 元模型**训练内样本**准确率 | 元 5 折 CV | val `test_like` |
|---|---|---|---|
| **OOF（正确做法）** | **83.16** | **83.06** | **88.17** |
| in-fold（泄漏） | **93.99** | **93.95** | **85.63** |
| 差 | **+10.83** | **+10.89** | **−2.54** |

- 泄漏把训练内样本准确率**虚抬 10.83 点**（83.16 → 93.99）——与方案 11 量化的 +13.15 同量级。

  学到"基础近乎完美"的权重，与真实留出分数**不匹配**。**OOF 既防虚高，又提升真实泛化**，方向一致。

### I. 资源与置换不变性自检

| 项 | 结果 |
|---|---|
| **候选顺序随机置换**（1 次 × 798 题） | 选择**答案**变化 **0 次**；选择**下标**仅 3 次变化（4 个候选特征完全相同时的精确并列）→ **PASS** |

### J. 失败分析（`results/failures.md`，test_like 42 错，其中 **3 个 8 基座全票一致地错**）

1. **全票一致**（square dancing，gold `2`）：解析值 `[48,48,45,2]`，6 个基座全部选 `48`。
   错答 `94−46` **算式自洽**，只是基数取错——`NGSC` 无法检测（它的代数是对的）。
2. **全票一致**（Manny 派，gold `4`）：解析值 `[5,5,240,4]`，全票选 `5`（对"1 pie 的份额"取错）。
3. **多数一致地错**（Yun 回形针，gold `9`）：解析值 `[9,17,17,17]`；三个候选把"多 1/4"错算成 `8+2+7=17`，
   `shape` 与 `NGSC` 都站在多数一边（17 同样整数、同样可达、算式同样自洽）。

**共同点**：残余错误全是**语义/建模误解**（错误候选的**算术本身正确**），这正是方案 14/15 各自
"数值证据无用"结论的微观复现——它们能修的是"数值形态/可达性不一致"的题，修不了"读错题"的题。

## 结论 (Conclusion)

- **假设成立到什么程度：部分成立，且必须分指标陈述。**
  1. ✅ **`shape`（答案形态）是有效的正交证据**：接嵌入后单独带来 **+1.13（对 content4）/ +1.69（对方案 11 配置）**，
     k=1 **+5.27**，且**不牺牲 k≥2**。这是本方案最可靠的结论，直接回答了方案 14 悬而未决的问题
     （"`shape` 的 +4.5 能否叠加到最强 stacker 上"——能，但幅度收缩到 +1.1~+1.7）。
  2. ⚠️ **`NGSC`（算式重执行）被强基线大幅吸收**：**单独加入边际 0.00**；只有在与 `shape` 同处一个基座集合时
     才显 +0.28（LOO）。这与方案 15 的结论一致：**新证据在强基线上增益迅速衰减**。
  3. ✅ **validation 上超过 87.32**：`test_like` **88.17 > 87.32（+0.85）**。
  4. ❌ **真实 test 上未超过 83.30**：**83.30 = 83.30（+0.00）**。42/467 个选择与方案 11 不同，但净正确数恰好相同（389）。
- **与基线相比的净增益与代价**：相对众数投票，`test_like` **+19.16**、真实 test **+14.14**；
  相对方案 11，`test_like` **+0.85**、真实 test **±0.00**。代价 = 60 KB 资产（≈方案 11 的 1.0 倍）、
  5.4 s 评测（+1 s）、≈6 min 训练。**收益/代价划算**（资产与耗时几乎不变，val 主指标提升）。
- **对 5 个研究问题的贡献**
  1. **读推理是否有用**：有。但**只有当推理内容被"读成答案形态"时**才有效（`shape` 接嵌入 +1.13~+1.69）；
     把推理**当作算式去重执行**（`NGSC`）边际为 0——**"读推理"的价值在表层统计，不在符号验算**。
  2. **错答案为何可信**：因为它们**算术正确、只是建模错**（失败分析 3/3 属此类）。它们的答案形态
     （整数、量级、可达性）与正确答案**无法区分**。
  3. **是否该跨候选比较**：该。全部增益来自题内相对量（z/一致性）与**成对损失**；同一元特征换成逐候选损失掉 **3.66**。
  4. **能否识别不确定性**：能识别一部分。k=1 69.30 vs k=3 100.0；8 基座**全票一致**时错误率更高
     （42 错里 3 个属此类）。但分数间隔仍不携带可靠信息（未做弃权）。
  5. **更多计算是否划算**：**不划算**。`NGSC` 的闭包与重执行是廉价计算却几乎无增益；
    真正有用的是**已有证据族（嵌入）与新证据（答案形态）的"正确拼接方式"**，而不是新算法或更大模型。
- **下一步可迭代方向**
  ① 把 `shape` 进一步**问题条件化**（例如"答案量级 vs 题干量级的相对秩"），v 与题干单位/量纲对齐；
  ② 用 K=20/留一法进一步压低 OOF→全量漂移；
  ③ 对 `NGSC` 改作**辅助任务**（伪标签一致性正则），让嵌入在不并联的前提下吸收它。
- **不建议继续的方向**
  ① 继续加深数值闭包 / 扩大算式重执行（本方案 + 方案 14/15 三方一致：低产）；
  ② 继续增加基础模型数量（`literal_8` 字面 8 路反而把 k2 打到 92.86）；
  ③ 元模型加容量（逐候选损失 −3.66）；
  ④ 任何位置/ID 先验或 in-fold 分数刷数字。

## 复现

```bash
# 训练（固定种子 20260916；只用 train 拟合 + OOF；validation 仅用于并列打破）
cd solutions/16_final_fusion
python train.py                 # ≈6 min（首跑含特征/基础分数缓存；重复运行 artifacts 逐字节一致）

# 评测（从 solutions/00_shared/ 运行）
python harness.py --method ../16_final_fusion/method.py \
  --checkpoint ../16_final_fusion/artifacts --split validation \
  --output ../16_final_fusion/results/validation.json

# 真实 test（官方 pipeline，只跑一次）
cd ../../code
./.venv/Scripts/python.exe predict.py --method ../solutions/16_final_fusion/method.py \
  --checkpoint ../solutions/16_final_fusion/artifacts --split test --output runs/t16.json
./.venv/Scripts/python.exe score_predictions.py --split test --predictions runs/t16.json \
  --output ../solutions/16_final_fusion/results/test.json
```

**铁律合规**：训练只用 `train`；`validation` 仅用于①元 CV 并列带的打破（协议指定）②报告指标；
`test` 参考**从未**用于训练/调参/选择——冻结全部完成后才跑一次官方 pipeline。无任何位置/ID 先验
（置换自检：答案变化 0/798）。

**产物**：`artifacts/{config.json, base_{text,embed,pair,pairab,shape,ngsc}.npz, meta.npz, SHA256SUMS.txt}`（60 125 B）；
`results/{validation.json, test.json, ablations.json, encoding_probe.json, failures.md}`。
`_cache/`（特征与基础分数缓存）与 `_scratch/`（开发期探索）不是交付物。

**自包含**：`f16_features.py` / `train.py` / `method.py` 全部为本方案独立实现，
不 import 其它方案代码（仅通过 `solutions/00_shared/harness.py` 的数据加载与协议）。
